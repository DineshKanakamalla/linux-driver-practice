# 01 - Hello World LKM

A minimal Linux Loadable Kernel Module (LKM) used to understand the basic
module lifecycle, Kbuild workflow, kernel logging, module metadata,
loading/unloading, and basic debugging.

## Objective

Build and investigate a minimal out-of-tree Linux kernel module.

The exercise focuses on understanding:

```text
Source Code
    ↓
Kbuild
    ↓
Kernel Object (.ko)
    ↓
insmod
    ↓
Module Initialization
    ↓
Module LIVE
    ↓
rmmod
    ↓
Module Cleanup
```

## Source Code

The module contains:

```c
static int num = -100;
static char string[] = "Dinesh";

static int __init hello_mod_init(void)
{
    pr_info("Hello world %s\n", string);
    return 0;   /* 0 means success; non-zero means init failed */
}

static void __exit hello_mod_exit(void)
{
    pr_info("Good bye world %d\n", num);
}
```

The module registration is:

```c
module_init(hello_mod_init);
module_exit(hello_mod_exit);
```

`pr_info()` writes to the kernel log (visible via `dmesg`); there is no libc,
so `printf()` does not exist in kernel space.

## Header Files

### `<linux/module.h>`

Used for Linux kernel module infrastructure.

This exercise uses functionality such as:

```c
module_init()
module_exit()

MODULE_LICENSE()
MODULE_AUTHOR()
MODULE_DESCRIPTION()
```

### `<linux/init.h>`

Provides initialization-related annotations used here:

```c
__init
__exit
```

`__init` identifies code that is needed only during initialization.

`__exit` identifies cleanup code associated with module removal.

## Module Lifecycle

```text
                    hello.ko
                       │
                 sudo insmod
                       │
                       ▼
               module_init()
                       │
                       ▼
             hello_mod_init()
                       │
             ┌─────────┴─────────┐
             │                   │
          return 0          return -errno
             │                   │
             ▼                   ▼
        Module LIVE         Load FAILED
             │
        sudo rmmod
             │
             ▼
         module_exit()
             │
             ▼
       hello_mod_exit()
             │
             ▼
      Module REMOVED
```

## Build

Check that the kernel build directory exists:

```bash
ls -ld /lib/modules/$(uname -r)/build
```

Build the module:

```bash
make
```

Expected final artifact:

```text
hello.ko
```

Check:

```bash
ls -l hello.ko
```

## Clean

Remove generated Kbuild artifacts:

```bash
make clean
```

Then rebuild when required:

```bash
make
```

## Inspect Before Loading

Inspect the module metadata:

```bash
modinfo ./hello.ko
```

Useful fields include:

```text
filename
description
author
license
vermagic
depends
```

Check the ELF file:

```bash
file hello.ko
```

Inspect ELF sections:

```bash
readelf -S hello.ko
```

Inspect symbols:

```bash
readelf -s hello.ko
```

Filter the module's functions:

```bash
readelf -s hello.ko | grep hello_mod
```

## Load the Module

Load:

```bash
sudo insmod ./hello.ko
```

Check the command status:

```bash
echo $?
```

Successful insertion should normally produce:

```text
0
```

## Verify the Module

Check:

```bash
lsmod | grep hello
```

Inspect the loaded module:

```bash
cat /proc/modules | grep hello
```

Inspect sysfs:

```bash
ls -la /sys/module/hello/
```

Check the initialization state:

```bash
cat /sys/module/hello/initstate
```

Expected:

```text
live
```

## Kernel Logs

The module uses:

```c
pr_info()
```

The message is written to the kernel log rather than directly to the terminal.

Check:

```bash
sudo dmesg | tail -20
```

Expected message:

```text
Hello world Dinesh
```

```bash
sudo dmesg -w
```

Then load/unload the module from another terminal.

Unload using the module name:

```bash

```

Verify:


Check the kernel log:


## Module Information Through Sysfs

After loading:

```bash
sudo insmod ./hello.ko
```

Inspect:

```bash
ls -la /sys/module/hello/
```

Check:

```bash
cat /sys/module/hello/initstate
```

Expected:

```text

```

The exact contents of:

```text

```

depend on the kernel configuration and build environment.

Therefore, use:

```bash

```

## Understanding `__init` and `__exit`

The initialization function is declared:

```c
static int __init hello_mod_init(void)
```

The cleanup function is declared:

```c
static void __exit hello_mod_exit(void)
```

Investigate the resulting ELF sections:

```bash
readelf -S hello.ko | grep -E 'init|exit|text|data|rodata|bss'
```

Then inspect the symbols:

```bash
readelf -s hello.ko | grep hello_mod
```

The purpose of this experiment is to connect:

```text
C source
   ↓
__init / __exit
   ↓
ELF sections
   ↓
Kernel module loader
   ↓
Kernel memory management
```

## Initialization Failure Experiment

A module initialization function returns an `int`.

Successful initialization:

```c
return 0;
```

A failure can be reported using a negative errno value.

For example:

```c
return -EINVAL;
```

`EINVAL` represents an invalid argument.

After changing the code:

```bash
make clean
make
```

Attempt to load:

```bash
sudo insmod ./hello.ko
```

Check:

```bash
echo $?
```

and:

```bash
sudo dmesg | tail -20
```

You may see:

```text
insmod: ERROR: could not insert module ./hello.ko: Invalid parameters
```

The important observation is that the initialization function can execute
code such as:

```c
pr_info("Hello world %s\n", string);
```

before returning the error.

Therefore, seeing the log message does not necessarily mean that module
loading succeeded.

The return value determines whether initialization succeeds.

Restore:

```c
return 0;
```

after completing the experiment.

## Debugging Workflow

Use this workflow when investigating the module:

```text
1. Build
   ↓
2. modinfo
   ↓
3. insmod
   ↓
4. echo $?
   ↓
5. lsmod
   ↓
6. dmesg / journalctl
   ↓
7. /sys/module
   ↓
8. Exercise functionality
   ↓
9. rmmod
   ↓
10. Check logs
```

For real driver development, always investigate both:

```text
Success path
Failure path
```

## Generated Build Artifacts

After:

```bash
make
```

Kbuild may generate files such as:

```text
hello.o
hello.ko
hello.mod
hello.mod.c
hello.mod.o
Module.symvers
modules.order
```

Briefly:

| File             | Purpose                                  |
| ---------------- | ---------------------------------------- |
| `hello.o`        | Compiled object generated from `hello.c` |
| `hello.ko`       | Final loadable kernel module             |
| `hello.mod.c`    | Generated module metadata source         |
| `hello.mod.o`    | Compiled generated module metadata       |
| `hello.mod`      | Kbuild module information                |
| `Module.symvers` | Symbol/version information               |
| `modules.order`  | Module build ordering information        |

These files are generated and should not normally be edited manually.

## Key Takeaways

This exercise establishes the basic Linux kernel module model:

```text
module_init()
    ↓
initialization
    ↓
return 0
    ↓
module becomes LIVE
    ↓
module_exit()
    ↓
module removed
```

and the failure model:

```text
module_init()
    ↓
return -errno
    ↓
initialization failure
    ↓
module insertion fails
```

The next exercise builds on these concepts rather than replacing them.
